# Scanners scan the user's Watchlist, and whole-market breadth comes from FMP rather than yfinance

The three signal-based scanners (Dividend Ranking, Momentum Scanner, Pre-Squeeze Scanner) operate over the tickers in the user's Watchlist rather than over the whole US market, because yfinance — the project's existing market-data dependency — exposes no screener or bulk endpoint at all; it can only be queried one ticker at a time. Scanning even a few thousand tickers would mean thousands of sequential HTTP calls against an unofficial, rate-limited API that has already returned HTTP 429 during development. Constraining the universe to the Watchlist makes the scan finite, cheap, and cacheable, and it also matches how a single user actually works: they follow a couple dozen tickers, not the whole market. The one feature that genuinely needs whole-market data — Trending Stocks Today, whose entire point is "what moved across the market today" — cannot be built this way, so it uses Financial Modeling Prep, added as a new backend dependency specifically because its free tier uniquely exposes ready-made gainers/losers/most-active lists that need no per-ticker iteration. The resulting two-provider split is deliberate: yfinance for per-ticker depth over a small known universe, FMP for pre-aggregated market breadth. This also makes the previously unused Watchlist backend (model and CRUD router already existed with no frontend at all) the foundation of a whole feature area, which is why a Watchlist management UI ships as a prerequisite rather than as an afterthought.

## Destination

A **working** (not just planned) upgrade to the "AI Technical Signal" feature (`frontend/src/utils/aiTechnicalSignal.ts`, rendered in `frontend/src/pages/DashboardPage.tsx`): the existing deterministic indicators (RSI14, MACD 12/26/9, SMA20/50/200, volume ratio, Bollinger Band width) stay computed in the frontend exactly as today, but (a) the rule-based confidence-score pillar weights and the ATR-based trading-setup multipliers (1.5x stop-loss / 3.0x target) get backtested against real historical price outcomes and revised where the data warrants, and (b) a local LLM — run via Ollama on this machine, orchestrated from the FastAPI backend — reads the same computed indicators/zones and produces its own qualitative Thai-language analysis, shown **alongside** (never replacing) the deterministic score, so the numeric side stays auditable/testable while the reasoning gets genuinely smarter.

Reaching the end of this map means: the backtest has run and any weight/multiplier revisions are decided and applied, the chosen local model is installed and wired end-to-end from backend to UI, and the dashboard shows both the rule-based score and the LLM's view side by side — working code, not a handoff spec.

## Decisions so far

- [ติดตั้ง Ollama + ดึงโมเดล](issues/01-ollama-setup.md) — Ollama v0.32.6 installed; final candidate set is `scb10x/llama3.2-typhoon2-3b-instruct`, `qwen2.5:3b` (swapped in for the originally-planned 7b after a disk-space scare), and `llama3.2:3b`. `C:` free space is tight (~6GB) but stable.
- [เลือกโมเดล local LLM](issues/02-local-model-selection.md) — **`llama3.2:3b` is the chosen default**, on reasoning-quality grounds: it was the only candidate that correctly flagged a deliberately-planted RSI-overbought/bullish-MACD conflict instead of ignoring or misreading it, despite having the roughest Thai prose of the three. `scb10x/llama3.2-typhoon2-3b-instruct` (fastest, most fluent Thai, but got the conflict wrong twice) kept as a live alternative to revisit once ticket 04 lands a more structured prompt. `qwen2.5:3b` dropped — no compensating strength.
- [ออกแบบวิธี backtest](issues/03-backtest-methodology.md) — fixed 30–50 ticker representative basket (not the user's own portfolio, which is empty), 10 years of yfinance history, **two separate metrics**: confidence-score pillars validated via forward-return correlation (5/10/20-day windows), trading-setup ATR multipliers validated via hit-target-before-stop win rate (60-day expiry = neutral). Walk-forward validation (5y train / 1y test, rolled yearly, ~4–5 folds). Revise a number only if it wins ≥3-of-4–5 folds by a non-trivial margin.
- [สร้างและรัน backtest engine จริง](issues/06-backtest-implementation.md) — ran for real: 31-ticker basket, 331,683 records, 5 folds (2016–2026). **ATR multipliers: confirmed no revision, 1.5x/3.0x stays.** **Confidence-score pillars: all 5 showed near-zero, sign-flipping correlation with forward returns — no pillar demonstrated measurable predictive validity**, a bigger finding than "reweight the weak ones" since there's no strong pillar to anchor a revision to. Full report: [backtest_report.md](../../backend/app/backtest/results/backtest_report.md). Graduated a new decision — see [ทิศทางคะแนน confidence](issues/07-confidence-score-direction.md).
- [ทิศทางคะแนน confidence](issues/07-confidence-score-direction.md) — follow-up classification check found the *combined* BULLISH/BEARISH badge fared **worse** than the pillars alone: NEUTRAL-labeled days out-earned BULLISH-labeled days in 4/5 test folds at every horizon. Rejected "keep with a disclaimer" and "remove outright" — decided to pursue a **data-derived redesign** (fit real weights/coefficients from the backtest data, walk-forward validated) rather than another hand-guessed formula. Graduated into [ค้นคว้าและ fit สมการคะแนนใหม่](issues/08-fit-scoring-model.md).
- [ออกแบบ LLM integration contract](issues/04-llm-integration-contract.md) — on-demand button (not auto-trigger, `llama3.2:3b` takes ~39s) + per-(ticker,date) cache; structured JSON output (`sentiment`/`narrative`/`conflictingSignals`/`caveats`) not free text; fallback = error message + retry (never silently hide or fake-fallback to the old template); full `AiSignalMetrics` sent as input (including ticket 08's new fitted score); new router `POST /ai-narrative/analyze`. **Fact found, not decided**: Ollama currently only binds `127.0.0.1`, needs `OLLAMA_HOST=0.0.0.0` before the backend container can reach it via `host.docker.internal`. Graduated into [ต่อระบบ LLM จริง](issues/09-llm-backend-implementation.md).
- [Prototype: dual confidence display](issues/05-dual-display-prototype.md) — **DONE, shipped.** 3-variant live `/prototype` (sub-shape A, mounted in the real DashboardPage route with real data/latency). Chose side-by-side split (system score + AI Analyst simultaneously visible, per ticket 04's "alongside, never replacing" contract) over an inline-callout or tabbed-toggle treatment. Added a responsive breakpoint (collapses to 1 column under 880px) the prototype exposed as a real gap. Folded into production: `frontend/src/components/AiAnalystPanel.tsx` + `.ai-signal-split` in `theme.css`; prototype variants/switcher deleted. Verified live in-browser at both desktop and narrow widths. 53/53 test files, 462/462 tests passing.
- [ต่อระบบ LLM จริง](issues/09-llm-backend-implementation.md) — **DONE, shipped, verified live end-to-end (not just mocked tests).** Fixed Ollama networking (`OLLAMA_HOST=0.0.0.0`), new router `POST /ai-narrative/analyze`, in-memory (ticker,date) cache, frontend `useAiNarrative` hook + minimal UI wired into `DashboardPage.tsx`. Real browser test with live NVDA data produced a correct `BULLISH` read matching the data (no false conflict); a synthetic conflict scenario correctly produced `neutral` + named the conflict. Backend 263/263, frontend 462/462 tests pass. **Caveat found, not fixed**: the (ticker,date) cache doesn't invalidate on same-day metrics changes — matches ticket 04's literal decision, but means a fast-moving stock won't get a same-day-refreshed AI read.
- [ค้นคว้าและ fit สมการคะแนนใหม่](issues/08-fit-scoring-model.md) — **DONE, shipped.** Regression (raw features → forward return) failed (negative out-of-sample R²); classification (raw features → hit-target-before-stop on the baseline setup) showed real walk-forward-validated skill (beat majority-class baseline 4/5 folds, AUC 0.60–0.78). `calcConfidenceScore` in `frontend/src/utils/aiTechnicalSignal.ts` rewritten to the fitted logistic-regression formula (9 features, sigmoid) — implementation handed off to and completed by Antigravity (`.agents/worker_signal_fit1/`), independently audited afterward in this session: coefficients hand-verified against 2 test cases, scope confirmed confined to the 3 permitted files, `npm test` re-run independently — 52/52 files, 457/457 tests pass. `pillars` now reports signed feature contributions instead of the old 5 named buckets; badge/type thresholds recentered around the ~58% baseline win rate.

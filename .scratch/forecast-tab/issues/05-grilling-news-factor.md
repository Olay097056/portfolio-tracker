# 05 - Grilling: ปลุก news factor ที่ hardcode 0 ให้กลับมาทำงาน

Type: grilling

Blocked by: 01

## Answer (user-confirmed 2026-08-09)

1. **สูตรรวม: ถ่วงน้ำหนักตามความสด** — ข่าว 0-2 วันเต็ม, 3-5 วันครึ่ง, 6-7 วันจาง แล้ว cap ที่ 100
2. **หน้าต่างเวลา: 7 วัน** — นับข่าวย้อนหลัง 7 วัน สอดคล้องกับน้ำหนักข้อ 1
3. **ทิศทาง: บวกเท่ากันทุกโมเดลที่เกี่ยว** — ใช้ impact_score อย่างเดียว ไม่เพิ่ม field ทิศทาง (ไม่ขยาย scope)
4. **ไม่มีข่าว: ทิ้ง (drop)** — factor ไม่นับใน denominator เหมือน indicator ที่ไม่มีข้อมูล (ตรงหลักไม่แต่ง) — คะแนนเต็มยังถึง 100 ได้
5. **simulator: ปรับได้** — slider "ระดับข่าวแรง" 0-100 ต่อโมเดล (จำลอง "ถ้ามีข่าวแรงระดับ X เกี่ยวกับโมเดล Y")
6. **ประวัติ: ยอมรับ + เส้นแบ่ง** — แสดงเส้นแบ่งวันที่เริ่มนับ news ในกราฟประวัติ ("คะแนนก่อน/หลังรวม news factor") — ประวัติเดิมยังมีค่า

## Question

`news` factor คิดเป็น **15 คะแนนเต็มจาก 100** ของทุกโมเดล แต่ `model_service.py:721` เขียนไว้ว่า

```python
# news: no news feed in this app yet — honest 0 (not fabricated).
news = 0.0
```

คอมเมนต์นั้น**ไม่จริงแล้ว** — แอปมี tab ข่าวสาร มี `news_service.py` และมีข่าวในฐานข้อมูล ผลคือทุกโมเดลถูกตัดเพดานคะแนนเหลือ 85 โดยไม่มีใครรู้ และ simulator ที่กำลังจะสร้างก็จะมีตัวแปรหนึ่งที่ขยับไม่ได้เลย

ข่าวควรแปลงเป็นคะแนน 0-100 ต่อโมเดลยังไง และ simulator ให้ปรับอะไรได้

## ข้อเท็จจริงตั้งต้น (ตรวจแล้ว — วัตถุดิบมีครบ ไม่ต้องเก็บข้อมูลใหม่)

ตาราง `news_items` (`news_service.py:70-86`) มีอยู่แล้ว:
- `impact_score` — 0-100 ให้โดย DeepSeek ("ข่าวนี้มีโอกาสขยับตลาดพันธบัตร/หุ้นสหรัฐฯ แค่ไหน")
- `related_models` — **JSON list ของ model id** ที่ DeepSeek จับคู่ให้แล้ว
- `published_at`, `category`, `analysis_th`

แปลว่าการจับคู่ข่าว → โมเดล มีข้อมูลรองรับอยู่แล้ว ไม่ต้องสร้างใหม่

## ตัวเลือกที่ต้องตัดสินใจ (ถาม user ทีละข้อ)

1. **สูตรรวมคะแนน** — ข่าวหลายชิ้นที่ `related_models` มีโมเดลนี้ จะรวมเป็นคะแนนเดียว 0-100 ยังไง: ค่าสูงสุด, ค่าเฉลี่ย, ผลรวมมีเพดาน, หรือถ่วงน้ำหนักตามความสดของข่าว
2. **หน้าต่างเวลา** — นับข่าวย้อนหลังกี่วัน ข่าวเก่าควรจางลงยังไง (จางแบบเชิงเส้น / ครึ่งชีวิต / ตัดตรงๆ)
3. **ทิศทาง** — `impact_score` วัด "แรง" ไม่ได้วัด "ดี/ร้าย" ข่าวแรงๆ ควรบวกคะแนนให้ทุกโมเดลที่เกี่ยวเท่ากันหรือ? โมเดล `bank-run` กับ `recovery-reflation` ไม่ควรได้คะแนนข่าวเหมือนกันจากข่าวเดียวกัน — ต้องมีทิศทางไหม ถ้าต้อง เอามาจากไหน (ต้องเพิ่ม field ที่ DeepSeek ให้ = ขยาย scope)
4. **ไม่มีข่าวเลย** — คะแนน news = 0 (เหมือนตอนนี้) หรือควรถูก "ทิ้ง" แบบเดียวกับ indicator ที่ไม่มีข้อมูล (ไม่นับใน denominator) — สองอย่างนี้ให้คะแนนรวมต่างกันมาก และข้อหลังตรงกับหลัก "ไม่แต่งตัวเลข" ของโปรเจคมากกว่า
5. **simulator ปรับอะไรได้** — ตัวเลข news factor ตรงๆ (0-100), หรือจำลองเป็น "มีข่าวแรงระดับ X เกี่ยวกับโมเดล Y", หรือไม่ให้ปรับเลย (แสดงค่าจริงอย่างเดียว) — ขึ้นกับผล ticket 01 ว่าต้นฉบับทำแบบไหน
6. **ผลข้างเคียงที่ต้องยอมรับ** — ปลุก news factor แล้ว **คะแนนทุกโมเดลจะเปลี่ยนทันที** และ `model_score_history` ที่สะสมมา (1794 แถว) จะกลายเป็นคนละมาตรวัดกับข้อมูลใหม่ ยอมรับได้ไหม หรือต้องมีเส้นแบ่ง/หมายเหตุในกราฟประวัติ

## เป้าหมาย

ได้สูตร news factor ที่เขียนลง spec ได้ + ตัดสินว่า simulator ปรับข่าวได้แค่ไหน + ยอมรับผลต่อประวัติคะแนนอย่างรู้ตัว → บันทึกเป็น ## Answer

**หมายเหตุ scope:** ถ้า ticket 01 พบว่าต้นฉบับ**ไม่มี**ตัวแปรข่าวให้ปรับเลย ให้เสนอ user ว่าจะยังปลุก news factor อยู่ไหม (user เลือกให้อยู่ในแผนแล้วเมื่อ 2026-08-09 แต่เหตุผลอาจเปลี่ยนถ้าต้นฉบับไม่มี) — ถ้า user ถอย ให้ปิดเป็น out of scope ไม่ใช่ resolve

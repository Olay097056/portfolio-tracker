## ตัวเลือกที่ต้องตัดสินใจ (ถาม user ทีละข้อ)

1. **กราฟ equity** — ต้นฉบับหัวข้อ "ผลงานการแข่งขัน" มี 4 โหมด (`% กำไร` / `$ equity` / `P&L ปิดแล้ว` / `เทียบต้นช่วง`) × ช่วงเวลา (24h/7d/30d/ทั้งหมด) × สเกล (พอดีข้อมูล/เต็มช่วง)
   ทีมเดียวยังต้องการกราฟไหม? ถ้าเอา — เอากี่โหมด? (เคยมีแล้วถูกลบใน commit `3cf88fe` · ตาราง `trade_snapshots` มีข้อมูลอยู่แล้ว)
2. **สวิตช์หลัก** — เบรกฉุกเฉินคุมค่าใช้จ่าย ไม่เกี่ยวกับการแข่ง — เอากลับไหม (backend มี `master_on` อยู่แล้วหรือเปล่า ให้เช็ค)
3. **โควตาเทิร์น + เทิร์นถัดไป** — ตัวคุมค่าใช้จ่ายโดยตรง เอากลับไหม
4. **ออเดอร์ที่ตั้งไว้** (รอเข้า/เข้าแล้ว/ยกเลิก/หมดอายุ/ถูกปฏิเสธ) — ต้นฉบับมีระบบ limit order ของเราเปิดไม้ที่ราคาตลาดทันที เอาไหม (งานใหญ่ — เพิ่ม state machine ของออเดอร์)
5. **สรุปประจำวัน / รายเดือน** — แบบทีมเดียว (ไม่มีอันดับ) ยังมีประโยชน์ไหม ใครเขียน (LLM = เพิ่มคอล / ตัวเลขล้วน = ถูกกว่า)
6. **คำสั่งโต๊ะกลาง (directive 📌)** — user พิมพ์คำสั่งให้ทีมแล้วมันมีผลต่อการตัดสินใจ — เอาไหม (`directive_md` มี field อยู่แล้วแต่ยังไม่ได้ใช้)
7. **หน้ารายละเอียดทีม** (`TeamDetailPage.tsx` 227 บรรทัด) — ต้นฉบับมี 6 นักวิเคราะห์ + ธรรมนูญทีม + ประชุม + คลังความรู้ ของเราครบแค่ไหน (ticket 01 ตอบ) แล้วอยากได้อะไรเพิ่ม
8. **เป้ารายเดือน/สัปดาห์** — ต้นฉบับให้หัวหน้าทีมตั้งเป้าเอง ของเราตั้งค่าคงที่ — เอาแบบไหน

## Answer (user-confirmed 2026-08-09)

1. **ขอบเขตที่กล้าอ้าง: (b) "สัญญาณที่มีสิทธิ์เกิด"** — โมเดลผ่านเกณฑ์ 40 แล้ว + ระบุชัดว่ายังต้องรอ TA ยืนยัน (ta_score ≥ 50) — ไม่ดึง TA จริง ไม่โกหก
2. **สัญญาณที่เปิดอยู่: บอกทั้งสองทาง** — สัญญาณ "มีสิทธิ์เกิดใหม่" (โมเดลข้าม 40) + สัญญาณ active ที่จะ "อ่อนแรง" (หลุดต่ำกว่า 40) + คำนวณ model_conviction ใหม่ตามคะแนนจำลอง
3. **แสดงที่ไหน: ในหน้าจำลองเอง** — section "ผลต่อสัญญาณเทรด" ใต้รายการโมเดล (ไม่สลับหน้า)
4. **ห้าม persist เด็ดขาด** — สัญญาณจำลองไม่เขียนลง `trading_signals` เลย (คำนวณสดในหน่วยความจำแล้วทิ้ง) — ข้อห้ามใน spec
5. **ถ้อยคำเตือน:** "การจำลองเป็นค่าประมาณทิศทาง — ไม่ใช่คำแนะนำการลงทุน และไม่ใช่สัญญาณจริง" (สั้น ใต้ปุ่มรีเซ็ต เหมือนต้นฉบับ)

## Question

ปรับตัวแปรมหภาคแล้ว **สัญญาณเทรดจะเกิดหรือหายไปตัวไหนบ้าง** — แสดงยังไงให้ซื่อสัตย์ ทั้งที่ simulator ขยับได้แค่ครึ่งเดียวของเงื่อนไข

## ปัญหาแกนกลาง (ตรวจแล้ว)

สัญญาณเทรดเกิดเมื่อเข้าเงื่อนไข **สองข้อพร้อมกัน** (จากแผนที่ `signals-tab` ticket 02):

1. **model score ≥ 40** ← มาจาก ctx **จำลองได้**
2. **ta_score ≥ 50** ← มาจากแท่งเทียน yfinance ผ่าน TA engine 6 เงื่อนไข (`price_vs_ema20`, `ema20_vs_sma50`, `rsi_zone`, `macd_state`, `bb_room`, `stoch_confirm`) **ไม่ได้อยู่ใน ctx จำลองไม่ได้**

แปลว่าคำถาม "ถ้า VIX พุ่ง 40 จะมีสัญญาณอะไรเกิด" ตอบได้แค่ครึ่งเดียวเสมอ ถ้าออกแบบไม่ดี UI จะบอกผู้ใช้ว่า "จะเกิดสัญญาณ X" ทั้งที่ TA อาจไม่ผ่าน — นั่นคือการโกหก

## ตัวเลือกที่ต้องตัดสินใจ (ถาม user ทีละข้อ)

1. **ขอบเขตที่กล้าอ้าง** —
   - (a) แสดงแค่ **สถานะโมเดล** ที่จะเปลี่ยน (inactive → building → active ตามเกณฑ์ 40/60) ไม่พูดถึงสัญญาณเลย — ซื่อสัตย์ที่สุด แต่ตอบไม่ตรงคำถามที่ user ตั้งไว้
   - (b) แสดง **"สัญญาณที่มีสิทธิ์เกิด"** = โมเดลผ่านเกณฑ์แล้ว **และระบุชัดว่ายังต้องรอ TA ยืนยัน** — ตอบตรงคำถามและยังไม่โกหก
   - (c) ใช้ **ta_score ปัจจุบันจริง** ของแต่ละสินทรัพย์เป็นค่าคงที่ แล้วบอกว่า "ถ้า TA ยังเป็นแบบวันนี้ สัญญาณเหล่านี้จะเกิด" — แม่นที่สุด แต่ต้องดึง TA จริงตอนจำลอง (ช้าลง) และผู้ใช้อาจลืมเงื่อนไข "ถ้า TA ยังเหมือนวันนี้"
   - ความเห็นตั้งต้น: (c) ถ้าเร็วพอ ไม่งั้น (b)
2. **สัญญาณที่เปิดอยู่ตอนนี้** — จำลองแล้วบอกไหมว่าสัญญาณที่ active อยู่จะ "อ่อนแรง" (โมเดลหลุดต่ำกว่า 40)? และคำนวณ `signal_strength` ใหม่ไหม (`model_conviction` เป็น 1 ใน 5 factor และมันมาจากคะแนนโมเดลตรงๆ)
3. **แสดงที่ไหน** — ในหน้าจำลองสถานการณ์เอง หรือกระโดดไป tab สัญญาณเทรดพร้อม state จำลอง
4. **ห้ามเขียนลง DB** — สัญญาณจำลอง **ต้องไม่** ถูก persist ลงตาราง `trading_signals` เด็ดขาด (จะปนกับสถิติ win rate จริง) ยืนยันข้อนี้กับ user แล้วเขียนเป็นข้อห้ามใน spec
5. **ถ้อยคำเตือน** — ข้อความไทยที่บอกผู้ใช้ว่านี่คือสถานการณ์สมมติ ไม่ใช่คำแนะนำการลงทุน

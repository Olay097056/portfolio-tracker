## ทำไมต้องวัดก่อนสร้าง

ต้นฉบับเก็บ `llm_calls / tokens_in / tokens_out` ลงตารางทุกการประชุม — เขาไม่ได้ใส่เล่นๆ ถ้าที่นั่ง 5 คน × 7 เฟส × 2 เทิร์น = 70 คอลต่อประชุม แล้ว trigger อัตโนมัติเปิดประชุมวันละ 5 ครั้ง = 350 คอล/วัน บน DeepSeek ที่ user จ่ายเอง — ตัวเลขนี้ต้องรู้**ก่อน**เขียนเครื่องยนต์ ไม่ใช่หลัง

และคำถามที่แพงกว่าเงิน: **ผลมันดีพอไหม** ถ้า 5 บุคลิกจากโมเดลเดียวกันออกมาเห็นด้วยกันหมดทุกข้อ ก็ไม่มีเหตุผลจะสร้างระบบ 7 เฟสตั้งแต่แรก — จบที่เรียก DeepSeek ครั้งเดียวก็ได้ผลเท่ากันแต่ถูกกว่า 70 เท่า

## สิ่งที่ต้องเอาให้ user ตัดสิน (HITL — ห้ามตัดสินเอง)

1. **ต้นทุนต่อประชุม** เป็นตัวเลขจริง + ประมาณการต่อวันถ้าเปิด trigger อัตโนมัติ → user กำหนดเพดาน
2. **บทสนทนาเต็มฉบับ** ให้ user อ่าน — มันเถียงกันจริงหรือพยักหน้าตามกันหมด?
3. **มติที่ได้** — ใช้งานได้จริงไหม หรือเป็นคำกว้างๆ ที่ไม่ช่วยตัดสินใจอะไร
4. **มันแต่งตัวเลขไหม** — ตรวจทุกตัวเลขในบทสนทนาว่าตรงกับข้อมูลที่ป้อนเข้าไปจริง (นี่คือหลักห้ามละเมิดข้อ 2 ของแผน)
5. **คำถามชี้ขาด**: 7 เฟสให้ผลดีกว่าเรียก DeepSeek ครั้งเดียวจริงไหม — **ต้องรัน baseline เทียบด้วย** (เรียกครั้งเดียวขอสรุปสถานการณ์จาก input ชุดเดียวกัน) แล้ววางคู่กันให้ user เทียบ

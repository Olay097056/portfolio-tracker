## สิ่งที่ต้องทำ

เขียน `docs/specs/<วันที่>-forecast-scenario-simulation.md` ตามฟอร์แมตของ spec ที่มีอยู่แล้วใน `docs/specs/` (อ่าน `2026-08-08-macro-dashboard.md` เป็นแบบ — มันขยายมา 3 ครั้งและเป็นตัวอย่างที่ดีที่สุดของฟอร์แมตนี้)

ต้องครบทุกหัวข้อนี้:

1. **ขอบเขต** — ทำอะไร ไม่ทำอะไร (คัดจากช่อง Out of scope ของแผนที่มาใส่ตรงๆ เพื่อให้คนอ่าน spec ไม่ต้องเดา)
2. **ชุดตัวแปรที่ปรับได้** — ตารางเต็ม: key ใน ctx, ชื่อไทย, หน่วย, ช่วง, ขั้น, ค่าเริ่มต้น, กติกาการพันกัน (จาก ticket 03)
3. **สัญญา API** — endpoint, request/response schema เต็ม, การจัดการ error, กติกา cache/baseline (จาก ticket 04)
4. **สูตร news factor** — สูตรรวมคะแนน หน้าต่างเวลา การจัดการกรณีไม่มีข่าว และผลต่อ `model_score_history` เดิม (จาก ticket 05)
5. **ผลต่อสัญญาณเทรด** — ขอบเขตที่กล้าอ้าง วิธีแสดง และ**ข้อห้ามเรื่อง persist ลง `trading_signals`** (จาก ticket 06)
6. **UI** — layout, การแยกค่าสมมติจากค่าจริง, สถานะกำลังคำนวณ, copy ภาษาไทยทั้งหมด, พฤติกรรมบนจอเล็ก (จาก ticket 07 + prototype ที่ลิงก์ไว้)
7. **กลยุทธ์การเทสต์** — เทสต์อะไรที่ backend เทสต์อะไรที่ frontend เคสขอบมีอะไร (โดยเฉพาะ: override ค่านอกช่วง, ตัวแปรที่ไม่มีข้อมูลจริง, ไม่มีข่าวเลย, ทุกโมเดลหลุดเกณฑ์พร้อมกัน)
8. **หลักการที่ห้ามละเมิด** — ไม่แต่งตัวเลข, ค่าจำลองต้องแยกจากค่าจริงเสมอ, ห้ามเขียนสัญญาณจำลองลง DB
9. **ลำดับการลงมือ** — แนะนำว่าโมเดลที่มาทำต่อควรเริ่มจากอะไร (backend endpoint → เทสต์ → UI → ต่อ sub-tab ที่ 7 ใน `BondCrisisPage.tsx`)

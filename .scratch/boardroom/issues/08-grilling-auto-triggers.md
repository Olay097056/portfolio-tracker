# 08 - Grilling: trigger อัตโนมัติ 4 แบบ — เปิดประชุมเองเมื่อไหร่

Type: grilling
Status: closed
Claimed: hermes/2026-08-09
Blocked by: 03, 06

## Question

ระบบควรเปิดประชุมเองเมื่อไหร่ และเราจะกันไม่ให้มันเปิดรัวจนเผาเงินยังไง?

ต้นฉบับมี 4 trigger: **เปิดโดยแอดมิน / เปิดจากข่าว / เปิดจากโมเดลขยับ / เปิดจากข่าวแดง** และ empty state ก็โฆษณาไว้ว่า *"ระบบจะเปิดวาระเองเมื่อมีข่าวแรง ตัวเลขโมเดลขยับ หรือประกาศข่าวแดง"*

## ทำไมถึงถูกบล็อกโดย 03 และ 06

ต้องรู้**ต้นทุนจริงต่อประชุม** (03) ก่อนถึงจะตั้งเกณฑ์ trigger ได้อย่างมีความหมาย — เกณฑ์หลวมไป = เปิดวันละ 20 ครั้ง = บิลบาน และต้องมีเครื่องยนต์ที่เดินได้จริง (06) ก่อนถึงจะทดสอบ trigger ได้

## ข้อเท็จจริงตั้งต้น (ตรวจแล้ว)

- **ข่าว**: `news_items` มี `impact_score` 0-100 (DeepSeek ให้) + `related_models` — เกณฑ์ "ข่าวแรง" มีวัตถุดิบพร้อม
- **โมเดลขยับ**: `model_score_history` เก็บคะแนนย้อนหลังทุกครั้งที่เรียก `/api/models` — เทียบ snapshot ล่าสุดกับก่อนหน้าได้ทันที
- **"ข่าวแดง" (ปฏิทิน)**: `macro_service` มีข้อมูลมหภาค แต่ **ยังไม่มีปฏิทินเศรษฐกิจ** ในแอป — ถ้าจะทำ trigger นี้ต้องหาแหล่งใหม่ (ขยาย scope)
- แอปไม่มี scheduler แยก — ทุก router ใช้ pattern cache 10 นาที คำนวณตอนมีคนเรียก ถ้าไม่มีใครเปิดแอป ก็ไม่มีอะไรรัน

## ตัวเลือกที่ต้องตัดสินใจ (ถาม user ทีละข้อ)

1. **เอา trigger อัตโนมัติไหม หรือแอดมินกดเองอย่างเดียวก็พอ** — ถามข้อนี้ก่อน เพราะถ้าตอบว่ากดเองพอ ทั้ง ticket จบตรงนี้ (และประหยัดที่สุด)
2. **เกณฑ์ "ข่าวแรง"** — `impact_score` เท่าไหร่ขึ้นไป? ต้องกี่ข่าวในกี่ชั่วโมง? วาระที่เปิดตั้งชื่อจากอะไร
3. **เกณฑ์ "โมเดลขยับ"** — ขยับกี่จุดใน snapshot เดียว? หรือข้ามเกณฑ์ 40/60 เท่านั้น? (ข้ามเกณฑ์เป็นเหตุการณ์ที่มีความหมายกว่าตัวเลขดิบ)
4. **"ข่าวแดง"** — ยอมรับว่ายังไม่มีปฏิทินในแอป จะ (ก) ตัด trigger นี้ทิ้ง (ข) หาแหล่งปฏิทินเพิ่ม (ขยาย scope) — ความเห็นตั้งต้น: **ตัดทิ้งไปก่อน** ทำทีหลังได้
5. **กลไกรัน** — ไม่มี scheduler จะตรวจ trigger ตอนไหน: ตอนเปิดหน้า Bond-crisis / ตอนเรียก `/api/models` / ต้องมี background job จริง
6. **เพดานกันเผาเงิน** — สูงสุดกี่ประชุมต่อวัน? cooldown ระหว่างประชุมกี่ชั่วโมง? **ต้องมี ไม่ใช่ตัวเลือก** — และถ้าชนเพดานให้แสดงให้ user เห็นว่าชน ไม่ใช่เงียบ
7. **ประชุมซ้ำวาระเดิม** — ข่าวเดียวกันมาสามสำนัก ต้องกันไม่ให้เปิดสามประชุมยังไง

## Answer

Grilling ครบ 7 ข้อ (2026-08-09) — user ตัดสิน: **ทำ auto-trigger แบบจำกัด** (ข่าว + โมเดลขยับ) — เปิด ticket 10 (task: trigger engine) แล้ว

### 1. ทำ (จำกัด) — ข่าว + โมเดลขยับ
ตัดสินทำ — ตัด "ข่าวแดง" (ข้อ 4) — คำโปรย empty state 07 ต้องเป็น: *"ยังไม่มีการประชุม — ระบบจะเปิดวาระเองเมื่อมีข่าวแรง หรือตัวเลขโมเดลขยับ"*

### 2. เกณฑ์ "ข่าวแรง"
- `news_impact_min = 70` (impact ≥70 = ข่าวแรงจริง ตาม prototype: 90/85/80) — 1 ข่าวก็เปิดได้
- `news_batch_hours = 6` — ข่าวแรงทั้งหมดในกรอบ 6 ชม. = 1 ประชุม
- ดูเฉพาะ `published_at` ใน 24 ชม. ย้อนหลัง
- วาระอัตโนมัติ: `"ประเมินตลาดหลังข่าว: <title_th ข่าว impact สูงสุด> (impact N) — โมเดลเกี่ยวข้อง: <related_models>"` → CEO ขยายในเฟส opening

### 3. เกณฑ์ "โมเดลขยับ" (2 ชั้น)
- ชั้น 1 (หลัก): โมเดลใด**ข้ามเกณฑ์ 40 หรือ 60** ระหว่าง snapshot 2 อันติด (ขึ้น/ลง) — "สัญญาณก่อตัว/ดับ"
- ชั้น 2 (รอง): คะแนนเปลี่ยน **≥ 8 จุดใน 6 ชม.** แม้ไม่ข้ามเกณฑ์
- วัดจาก `model_score_history` 2 แถวล่าสุด (timestamp ห่าง ≤ 6 ชม.)
- วาระ: `"โมเดล <name_th> ขยับ <old>→<new> (<+Δ>) — ข้ามเกณฑ์ 60"` / `"...ขยับ <+Δ> จุดใน 6 ชม."`

### 4. "ข่าวแดง" — ตัดทิ้ง (backlog)
**ทดสอบสด 3 แหล่งฟรีแล้วใช้ไม่ได้ทั้งหมด**: Finnhub calendar HTTP 403 (paid-only) · FMP economic-calendar HTTP 402 (paid-only) · TradingView endpoint HTTP 403 (unofficial) — ต้นฉบับใช้ TE (จ่าย) — ตัดก่อน บันทึก backlog: "รอ TE subscription หรือแหล่งฟรีที่น่าเชื่อถือ" — copy 07 ไม่มี "ข่าวแดง"

### 5. กลไกรัน — piggyback (ไม่มี scheduler ใหม่)
- `check_triggers(db)` เรียกจาก: `GET /api/boardroom/meetings` · หลัง news refresh · หลัง `/api/models`
- cooldown guard: ตรวจสูงสุด 1 ครั้ง/10 นาที (pattern cache เดิม)
- ปุ่ม/endpoint: `POST /api/boardroom/triggers/check` → `{triggered, meeting_id?, reason}`
- logic: single-user — ไม่มีใครเปิดแอป = ไม่เปิดประชุม = ไม่เสียเงิน (background 24/7 ไม่จำเป็น — backlog ถ้าอยากได้)

### 6. เพดานกันเผาเงิน
- `daily_cap = 6` ประชุม/วัน **นับรวม manual + auto** · `cooldown_minutes = 60` (auto เท่านั้น)
- ตารางใหม่ `boardroom_trigger_log` (checked_at, trigger_type, reason, skipped, skip_reason, meeting_id?)
- **เห็นว่าชน**: หน้า tab แสดงแถบ `"⏸ ข้ามการเปิดประชุมอัตโนมัติ N ครั้งวันนี้ — ชนเพดาน..."` — `GET /meetings` response เพิ่ม `today_meetings` + `trigger_log_today`

### 7. กันประชุมซ้ำวาระเดิม
- batch 6 ชม. = กัน "ข่าวเดียวกัน 3 สำนัก" (หลัก)
- เพิ่มคอลัมน์ `trigger_key` ใน boardroom_meetings: `news:<title_th ปกติ>` / `model:<model_id>:<40|60>` — ข้ามถ้าตรงกับประชุมที่จบภายใน 6 ชม. (log "ข่าวเดิมซ้ำ")
- manual ไม่มี dedupe

**ส่งต่อ:** ticket 10 (task: trigger engine) ได้ spec ครบทุกเกณฑ์ — ticket 07 ได้ copy empty state ที่แก้แล้ว + แถบ trigger log

**ห้ามแตะโค้ด production** — ticket `grilling`

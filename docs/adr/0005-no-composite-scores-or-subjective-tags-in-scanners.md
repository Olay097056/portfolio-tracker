# Scanners show raw signals in separate columns, never a composite score or a subjective tag

The stockvision-app draft that these scanner tabs are derived from gave every row a single headline "score" (Momentum Scanner weighted six sub-scores including a "social" component; Pre-Squeeze Scanner had its own score) and gave dividend rows subjective category tags ("เหมาะ DCA", "เหมาะ passive"). Inspection showed those numbers were hardcoded mock values with no formula behind them, and no weighting we could invent would be any more validated. Publishing a single number implies a tested model and invites the user to trust it over their own reading of the underlying data; the tags do the same thing in words. So each scanner presents its inputs as individually sourced, individually sortable columns — RSI, percent change, volume-versus-average, distance from the moving average, Bollinger Band width and its own-history percentile, ATR percent, gross and net dividend yield, payment frequency, dividend growth — and lets the single user weigh them. The trade-off is real and accepted: one sortable number is genuinely more convenient than seven columns, and a "top ten by score" ranking is easier to read at a glance. We give that up because fabricated authority is harder to withdraw than to withhold — once a score is displayed and relied upon, removing it is a regression, whereas adding one later (if a weighting is ever actually justified) is additive. The same reasoning removed the "social" signal outright: the project has no social-listening data source, so there is nothing to compute it from. This is the same never-fabricate-a-value rule the rest of the app already follows for missing prices and rates, applied to derived judgments rather than to raw data.

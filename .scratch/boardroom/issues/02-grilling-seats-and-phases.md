# 02 - Grilling: ออกแบบที่นั่ง (personas) + เฟส + turn plan

Type: grilling
Status: closed
Claimed: hermes/2026-08-09
Blocked by: 01

## Question

ห้องประชุมของ**เรา** มีใครนั่งบ้าง พูดลำดับไหน กี่เทิร์นต่อเฟส และแต่ละที่นั่งได้เห็นข้อมูลอะไร?

นี่คือ ticket ที่กำหนดต้นทุนทั้งระบบ — จำนวนที่นั่ง × เทิร์น × เฟส = จำนวนคอล DeepSeek ต่อการประชุมหนึ่งครั้ง

## ข้อเท็จจริงตั้งต้น (ตัดสินแล้ว อย่ารื้อ)

**user ตัดสิน 2026-08-09:** ต้นฉบับใช้ "หลายโมเดลหลายค่าย" แต่เราใช้ **DeepSeek `deepseek-v4-flash` ตัวเดียว แบ่งเป็นหลายบริบท/หลายบุคลิก** ให้ตรงคอนเซปต์ — ไม่ต้องหาโมเดลค่ายอื่นมาเพิ่ม

ผลที่ตามมาที่ต้องยอมรับตรงๆ และเขียนไว้ใน answer: บุคลิกที่มาจากโมเดลเดียวกัน **มีอคติร่วมกัน** (correlated bias) — มันจะเห็นด้วยกันเองง่ายกว่าโมเดลต่างค่ายจริง คำโปรยต้นฉบับที่ว่า "โต้แย้งกันเพื่อหาความจริง" จึงอ่อนลงโดยธรรมชาติ ต้องออกแบบ prompt ให้บังคับการค้านจริงๆ ไม่ใช่หวังให้มันค้านกันเอง

## ตัวเลือกที่ต้องตัดสินใจ (ถาม user ทีละข้อ ตาม /grilling)

1. **จำนวนที่นั่ง** — ต้นฉบับมีกี่ที่นั่ง (จาก ticket 01) เราเอาเท่านั้นไหม หรือลดลง? ทุกที่นั่งที่เพิ่ม = คอล DeepSeek เพิ่มทุกเฟส เสนอตัวเลขพร้อมต้นทุนโดยประมาณให้ user เลือก
2. **บทบาทแต่ละที่นั่ง** — ต้นฉบับมี "เจมส์ (CEO)" เป็นคนสรุป เราต้องการบทบาทอะไรบ้าง (เช่น สายมหภาค / สายเครดิต / สายเทคนิคอล / คนค้าน (devil's advocate) / คนตรวจข้อเท็จจริง / CEO ผู้สรุป) — **ที่นั่ง "คนค้าน" สำคัญเป็นพิเศษ** เพราะเป็นตัวชดเชยปัญหา correlated bias ข้างบน
3. **แต่ละที่นั่งเห็นข้อมูลอะไร** — เห็น ctx มหภาคทั้ง 27 คีย์เหมือนกันหมด หรือแบ่งกันดูคนละส่วนเพื่อให้มุมต่างจริง? (แบ่งกันดู = โต้แย้งมีเนื้อกว่า แต่เสี่ยงสรุปจากข้อมูลไม่ครบ)
4. **เฟสไหนบังคับ เฟสไหนข้ามได้** — 7 เฟสเต็มทุกครั้ง หรือประชุมสั้น/ยาวมีสองโหมด? (ประชุมสั้น = ถูกกว่ามาก ใช้กับ trigger อัตโนมัติ)
5. **กี่เทิร์นต่อเฟส** — เฟสโต้แย้งวนกี่รอบถึงพอ มีเงื่อนไขหยุดเร็วไหม (เช่น ทุกที่นั่งเห็นตรงกันแล้ว → ข้ามไปลงมติ)
6. **ภาษา** — บทสนทนาเป็นไทยล้วน หรือคิดเป็นอังกฤษแล้วสรุปไทย? (ไทยล้วนอ่านง่ายกว่าแต่โมเดลมักให้เหตุผลได้ดีกว่าเป็นอังกฤษ — และโทเคนไทยแพงกว่าอังกฤษต่อข้อความเท่ากัน)
7. **เพดานความปลอดภัย** — ถ้าประชุมวนไม่จบ/เฟสไม่คืบ จะตัดที่กี่คอลหรือกี่นาที (ต้องมี ไม่งั้นบั๊กเดียวเผาเงินได้ทั้งคืน)

## Answer

Grilling ครบ 7 ข้อ (2026-08-09) — user ยืนยันทุกข้อด้วย "เห็นด้วย" — ผังที่นั่ง + เฟส + turn plan + เพดานความปลอดภัย พร้อมส่งต่อ ticket 03

**ยอมรับตรงๆ (ตามข้อเท็จจริงตั้งต้น):** บุคลิก 7 ที่นั่งมาจาก DeepSeek `deepseek-v4-flash` โมเดลเดียวกัน → มี **correlated bias** (เห็นด้วยกันเองง่าย) — คำโปรย "โต้แย้งกันเพื่อหาความจริง" อ่อนลงโดยธรรมชาติ → ชดเชยด้วย (ก) ผู้ท้าทาย 2 คนเห็นข้อมูลคนละชุดกับนักวิเคราะห์ (ข) prompt บังคับค้าน 2 ทาง (ห้ามมัดมือชก) (ค) ผู้ท้าทาย A/B ถูกบังคับค้านคนละมุม

### 1. จำนวนที่นั่ง — 7 ที่นั่ง (ตัวเลือก ก)
`ceo` (เจมส์ CEO) · `research` (แมวมอง) · `challenger` ×2 · `macro` (มหภาค) · `credit` (เครดิต/บอนด์) · `technical` (เทคนิคอล)
- ตัดจากต้นฉบับ 9: `news`, `conspiracy` (ซ้อนกับมหภาค/เครดิต + เสี่ยงแต่งข่าว), `quant` (รวมเข้ากับมหภาค)
- **เก็บผู้ท้าทาย 2 คนครบ** — ชดเชย correlated bias + กลไกตรวจ 2/2 ของต้นฉบับต้องมีคนตรวจ 2 คน

### 2. บทบาท (ตารางเต็ม + จุดบังคับ prompt)
| ที่นั่ง | บทบาท | จุดบังคับ |
|---|---|---|
| เจมส์ (CEO) | เปิดวาระ + คำถามหลัก 5 ข้อ · สรุปมติ**จากข้อสรุปที่ผ่านการพิสูจน์เท่านั้น** (brByJames ตรงตัว) · ชี้ขาด knowledge proposal | ห้ามอ้างตัวเลขนอก ctx · ทุกข้อในมติต้องระบุที่มาหลักฐาน |
| แมวมอง | ค้นข้อมูลภายนอก R1..Rn + ตัวเลขที่ห้องขอ V1..Vn — **ไม่ให้ความเห็นตลาด** | ทุกข้อต้องมี source · ไม่มี → "หาไม่เจอ" |
| ผู้ท้าทาย A | คนค้านหลัก (มุมข้อมูล/ตัวเลข) · ตรวจตัวเลขซ้ำแหล่งอิสระ | **ค้านได้เฉพาะมีหลักฐาน หรือพูดตรงๆ ว่าไม่มีจุดอ่อน** — ห้ามค้านมัดมือชก |
| ผู้ท้าทาย B | คนค้านมุมสอง (มุมตรรกะ/สมมติฐาน) · ตรวจซ้ำ**คนละแหล่ง**กับ A → 2/2 | ต้องหามุมที่ A ยังไม่แตะ |
| นักเศรษฐศาสตร์มหภาค | ดอกเบี้ย เงินเฟ้อ นโยบาย วัฏจักร — เจ้าภาพ yield/rate | อ้างตัวเลข macro จาก ctx เท่านั้น |
| นักวิเคราะห์เครดิต/บอนด์ | สเปรด HY/IG, ผิดนัดชำระ, สภาพคล่อง — เจ้าภาพ spread | อ้าง spread/ราคาเฉพาะที่มีในข้อมูล |
| นักวิเคราะห์เทคนิคอล | แนวโน้ม/โมเมนตัม/ระดับสำคัญ — เจ้าภาพราคา (ทอง/น้ำมัน/ETF/FX) | ห้ามแต่งระดับจากความจำ |

### 3. แต่ละที่นั่งเห็นข้อมูลอะไร (ตัวเลือก ค — สายกลาง)
- **นักวิเคราะห์ 3 คน:** ctx ครบ (macro 27 คีย์ + market_prices + คะแนนโมเดล + ข่าว) + prompt บังคับ focus รายบทบาท
- **ผู้ท้าทาย A/B:** เห็น**เฉพาะ**ข้อกล่าวอ้าง + ตัวเลขจริงที่เกี่ยวข้อง + แหล่งอ้างอิง — **ไม่เห็นบทวิเคราะห์เต็มของคนอื่น** (กัน bias ที่ต้นตอ — ตรวจจากหลักฐาน ไม่เดาตามห้อง)
- **CEO:** เห็นสรุปครบ · **แมวมอง:** เห็นคำขอ + แหล่งที่ค้นได้ (ไม่ต้องเห็น ctx เต็ม)
- **ทุกที่นั่ง:** เห็น "ข้อมูลระบบ" (sysContext: วาระ, วันที่, สินทรัพย์, ราคาอ้างอิง ณ เปิดประชุม) + refs memory/knowledge (M../K..)

### 4. เฟสบังคับ/เสริม + 2 โหมด (ตามต้นฉบับ — stepper ฟิลเตอร์เฟสเสริมอยู่แล้ว)
- **บังคับ 5:** เปิดวาระ → นำเสนอ (blind round) → โต้แย้ง → ตรวจสอบ → ลงมติ
- **เสริม 3:** วิจัยภายนอก (โหมดเต็มเท่านั้น) · หาหลักฐานเพิ่ม (มี data_requests) · ตรวจตัวเลขภายนอก (มีคำขอผ่านเกณฑ์) — ไม่มีเงื่อนไข → แทรกข้อความ "ข้ามรอบ" ไม่ใช่เฟสเปล่า
- **2 โหมด เลือกอัตโนมัติจาก trigger_type:** `manual` → เต็ม (~26 คอล) · `news/model/calendar` → สั้น (~19 คอล) — ข่าว/ตัวเลขที่ trigger เกิดอยู่ใน ctx อยู่แล้ว ไม่เสียหาย
- ยังค้างจาก map: แหล่ง "วิจัยภายนอก" ตัดสินใน ticket 03/08 (RSS+macro เดิม หรือเพิ่มแหล่ง) — ไม่บล็อกโครงสร้างนี้

### 5. Turn plan (ตาราง) + หยุดเร็ว
| เฟส | ใคร | เทิร์น |
|---|---|---|
| เปิดวาระ | CEO | 1 |
| วิจัยภายนอก (เต็ม) | แมวมอง | 1 |
| นำเสนอ (blind) | มหภาค, เครดิต, เทคนิคอล, ท้าทาย A, ท้าทาย B | 5 |
| โต้แย้ง รอบ 1 | ทั้ง 5 | 5 |
| โต้แย้ง รอบ 2 (มีเงื่อนไข) | ทั้ง 5 | 5 |
| ตรวจสอบ | ท้าทาย A, ท้าทาย B | 2 |
| หาหลักฐานเพิ่ม (มีคำขอ) | แมวมอง 1 + ท้าทาย 2 | 3 |
| ตรวจตัวเลขภายนอก (มีคำขอผ่านเกณฑ์) | แมวมอง 1 + ท้าทาย 2 | 3 |
| ลงมติ | CEO | 1 |

รวม: **เต็ม 26 คอล (21 ถ้า unanimous ข้าม debate รอบ 2) · สั้น 19 คอล (14 ถ้าข้าม)** — message kinds ตามต้นฉบับ: brief/rebuttal/attack/evidence/review/research2/verify

**หยุดเร็ว 4 ข้อ:** (1) debate รอบ 2 ข้ามเมื่อ unanimous หลังรอบ 1 (consensus=unanimous/contested ตามต้นฉบับ) (2) เฟสเสริมข้ามเมื่อไม่มีคำขอผ่านเกณฑ์ (3) คอล error → "ข้ามที่นั่งนี้" เดินต่อ ไม่วนซ้ำ (4) ตัดที่ `max_llm_calls_per_meeting`

### 6. ภาษา — ไทยล้วน
- ต้นฉบับให้โมเดลพูดไทย (หลักฐาน: ตัวประมวลผลจัดการ `ท้าทายวาระ:`/`[มุมมอง]`/`[ข่าวลือ-ยังไม่ยืนยัน]` + error label ไทย) — ทำตาม
- prompt+ข้อมูล+output ภาษาเดียวกัน กันโมเดลสับสน · โทเคนแพงกว่า ~1.5–2 เท่าแต่จิ๊บจ๊อยเทียบงบ
- กันคุณภาพเสื่อมด้วย prompt design (บังคับ "พิจารณาทั้งสองด้าน → อ้างหลักฐาน → สรุป") — ticket 03 วัด real output ถ้า debate ไทยแย่จริง ค่อยสลับเฉพาะเฟส debate เป็นอังกฤษ

### 7. เพดานความปลอดภัย (ตัวเลขตั้งต้น — ปรับได้ใน settings)
| เพดาน | ค่า |
|---|---|
| max_llm_calls_per_meeting | 40 (เต็ม 26 + buffer) — เกิน → failed + error + resume |
| max_tokens_speech | 8,000 (ตรง news_service) |
| max_tokens_resolution | 8,000 |
| timeout ประชุม (เพิ่มเอง — single-process) | 30 นาที → force failed |
| timeout ต่อคอล (เพิ่มเอง) | 120s → error → ข้ามที่นั่ง |
| cooldown_minutes | 60 |
| daily_cap | 6 (อนุรักษ์นิยม — ต้นฉบับยอม 12) |

**กติกา error:** retry 1 ครั้งเฉพาะ transient → ล้มอีก = ข้ามที่นั่ง · โดนตัด = `failed` + เก็บ error + ปุ่ม "ประชุมต่อ" **ต่อจาก `current_turn` เดิม** (ไม่เริ่มใหม่) · resume นับเข้าเพดาน 40 เดิม (กัน loop ตัด→ต่อไม่รู้จบ)

**ต้นทุนโดยประมาณ/ประชุม:** เต็ม 26 คอล (~100–150k tokens) · สั้น 19 คอล (~75–120k tokens) — ตัวเลขจริง ticket 03 วัด

**ส่งต่อ:** ticket 03 ได้ผังครบ (7 ที่นั่ง + บทบาท + turn plan + ภาษา + เพดาน) — ticket 04 ได้กลไกผู้ท้าทาย/ตรวจสอบ · ticket 07 ได้ผัง UI + 2 โหมด

**ห้ามแตะโค้ด production** — ticket `grilling` ตัดสินใจอย่างเดียว

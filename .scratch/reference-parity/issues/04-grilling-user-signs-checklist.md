## ทำไมใบนี้ต้องเป็น HITL แท้ๆ

**agent ดูหน้าจริงของต้นฉบับไม่ได้** — มัน login-gated และ agent ห้ามล็อกอิน มีแต่ user ที่เห็นทั้งสองหน้าพร้อมกันได้

และรอบที่แล้วพังเพราะ agent ตัดสินเองว่า "ครบตามข้อบังคับ ticket แล้ว" ทั้งที่ของขาดเพียบ — **ใบนี้จึงห้าม agent ตัดสินว่าอะไรผ่านหรือไม่ผ่านโดยเด็ดขาด** หน้าที่ของ agent คือเดินรายการให้ user ดูทีละข้อและบันทึกคำตอบ

## วิธีทำ

1. เอาตารางจาก `docs/research/reference-parity-<วันที่>.md` มาเดิน **ทีละหน้า**
2. ต่อหนึ่งหน้า: บอก user ว่าหน้าไหน แล้วไล่รายการที่ติดสถานะ `ขาด` / `ต่าง` ให้ดูทีละกลุ่ม
   พร้อมข้อความไทยจริงของต้นฉบับ เพื่อให้ user หาบนหน้าจอเจอ
3. user ตัดสินต่อข้อ เป็น 1 ใน 3:
   - **เอา** — ต้องทำ (เข้าคิวแก้)
   - **ไม่เอา** — ย้ายไป Out of scope ของ map พร้อมเหตุผลสั้นๆ
   - **ทีหลัง** — ใส่ Backlog ไม่ใช่ blocker ของแผนนี้
4. บันทึกคำตอบกลับลงตารางเดิม (คอลัมน์ `คำตัดสิน`) — เอกสารนั้นคือแหล่งความจริงเดียว

## กติกาบังคับ

- **ห้ามรวบ** — ห้ามถามว่า "ทั้งหน้านี้เอาไหม" ต้องไล่รายข้อหรืออย่างน้อยทีละกลุ่มเล็ก
- **ห้ามเสนอความเห็นเป็นคำตัดสิน** — เสนอได้ แต่ต้องรอ user พูด
- ถ้า user บอกว่า "ไม่แน่ใจ ขอดูก่อน" → ใส่ **ทีหลัง** อย่าเดาว่าเอา
- ระหว่างทางถ้าเจอรายการที่ตารางบอก `มี` แต่ user เห็นแล้วบอกว่าไม่เหมือน → **แก้สถานะเป็น `ต่าง`** แล้วถามต่อ (แปลว่า ticket 01 ประเมินพลาด — บันทึกไว้ด้วย)
